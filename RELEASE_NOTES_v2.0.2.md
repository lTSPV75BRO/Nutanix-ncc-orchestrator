# NCC Orchestrator — v2.0.2

**Release date:** 2026-05-29
**Type:** Patch + maturity release. Recommended for everyone running v2.0.0 / v2.0.1.

> **Affiliation:** This is an independent open-source project. It is **not** affiliated with or endorsed by Nutanix, Inc. NCC and Nutanix are trademarks of their respective owners. The project is MIT licensed; see [`LICENSE`](LICENSE).

v2.0.2 is the largest stability + operability release on the v2 line so far. It ships:

- A complete fix for the path / CORS / IPv6 / extractor / uninstall regressions reported against v2.0.1's `cd bin && ./ncc-orchestrator …` flow.
- An end-to-end **trust and provenance** layer (Windows VERSIONINFO, signing hooks, `release-attestation.json`, CycloneDX SBOMs, SLSA build provenance).
- A new **operability** surface: `doctor`, `v2-status`, `--health-check`, `/metrics`, shell completions, one-command `docker compose`.
- **Standalone API / UI server** support: the api-server and ui-server now auto-detect a v2 stack the same way the orchestrator does, and helpfully redirect orchestrator-only subcommands.

None of these changes break existing scripts. Every flag-explicit invocation from v2.0.0 / v2.0.1 keeps working.

## Highlights

### Trust & provenance

| What | How |
| --- | --- |
| **Embedded build metadata** | Windows binaries now carry a full `VERSIONINFO` (Properties → Details → ProductName, FileDescription, CompanyName, LegalCopyright, LegalTrademarks). Includes an explicit non-affiliation disclaimer so the embedded fields cannot be misread as a vendor endorsement. Generated by `tools/winversioninfo`. |
| **Optional code signing** | `binaryGO.txt` has no-op-by-default hooks for macOS Developer ID + notarization (`codesign` + `xcrun notarytool`), Windows Authenticode (`osslsigncode`), and Linux GPG detached signatures. Activated by env vars; binaries still build unsigned without them. |
| **`ncc-orchestrator verify`** | New subcommand prints embedded version / git revision / build date / Go version / executable SHA-256, plus the project URL, license, and the non-affiliation disclaimer. Pairs with `checksums.txt` for a single-shot integrity check. |
| **`release-attestation.json`** | Hand-rolled per-release provenance manifest (artifacts + sizes + SHA-256s + git revision + build host + license + disclaimer) emitted alongside `checksums.txt`. Auditable without `gh` or `cosign`. |
| **CycloneDX SBOMs** | `binaryGO.txt` invokes `cyclonedx-gomod` to emit a CycloneDX 1.5 JSON SBOM for each binary (`bom-ncc-orchestrator.cdx.json`, `bom-ncc-api-server.cdx.json`, `bom-ncc-ui-server.cdx.json`). Drop-in for Trivy / Grype / Dependency-Track. |
| **SLSA build provenance** | New `.github/workflows/release.yml` builds via `binaryGO.txt`, then signs every artifact with `actions/attest-build-provenance@v2`. Consumers verify with `gh attestation verify`. |

See [`docs/SECURITY_AND_TRUST.md`](docs/SECURITY_AND_TRUST.md) for the full handler chart, OS-by-OS first-run guidance (Gatekeeper / SmartScreen / executable-bit), and verification commands.

### Operability

| Subcommand / endpoint | What it does |
| --- | --- |
| **`ncc-orchestrator doctor`** | Single-command diagnostic: runs `verify`, `v2-check`, `v2-status`, prints recent log tails, summarizes the environment (NCC_* env var **names** only), and writes a redacted support tarball (`ncc-support-<UTC-timestamp>.tar.gz`). Config secrets matching `password / secret / token / credential / api-key / client-id` are replaced with `***REDACTED***` before they enter the bundle. |
| **`ncc-orchestrator v2-status`** | Reads `<install-dir>/run/v2-*.pid`, checks each PID is alive, probes `/api/v1/health` on the API listener, and prints a status table (or JSON with `--json`). Tolerant of missing PID files (will report `missing-pid` rather than failing). |
| **`ncc-api-server --health-check`** | Probe-only mode: connects to its own `/api/v1/health` URL using the on-disk token and exits 0/1. Designed for Docker `HEALTHCHECK` and Kubernetes `livenessProbe`. The new `Dockerfile.api` already uses it instead of bundling `wget`/`curl`. |
| **`/metrics`** (api-server) | Prometheus exposition format on `GET /metrics`: build info, process uptime, run state + counters (`ncc_runs_triggered_total`, `ncc_runs_completed_total`, `ncc_runs_failed_total`), Go runtime stats, and rate-limiter counters. Auth-gated by default; pass `--metrics-public` for token-free scraping on private networks. |
| **`ncc-orchestrator completion bash\|zsh\|fish\|powershell`** | Shell-completion script generation (cobra built-in). Stays in lockstep with the actual subcommand / flag set automatically. |
| **`docker-compose.yml`** | One-command stack launch: `docker compose up -d` builds and runs both `ncc-api-server` and `ncc-ui-server` on a private bridge network, with the UI gated by the API's `service_healthy` condition (which uses `--health-check`). Token shared via a named volume; no token in env vars. |

### Standalone API / UI server

The api-server and ui-server now auto-detect a v2 stack the same way the orchestrator does. Running:

```bash
cd ncc-v2-stack-<os>-<arch>/bin
./ncc-api-server --listen 127.0.0.1:8081
```

…now resolves `--repo-root`, `--config-path`, `--output-dir`, `--log-dir`, `--token-file-path`, and `--orchestrator-bin` to the matching paths inside the extracted stack — no flags required for the common case. Symlink resolution is applied consistently (the same fix that v2-start / v2-bootstrap got in v2.0.0+).

When `ncc-api-server` or `ncc-ui-server` is invoked with an orchestrator-only subcommand (`update`, `v2-start`, `v2-status`, `doctor`, …), it now exits 2 with a helpful message that points at `bin/ncc-orchestrator <subcommand>` — instead of silently starting a server because Go's `flag` package treated the subcommand as a no-op positional arg.

Pinned by `TestApplyStackAwareDefaults_RespectsExplicitOverrides` (api-server), `TestUIExplicitFlagSet` (ui-server), and the layout tests in `internal/v2layout/`.

## Bug fixes (the v2.0.1 → v2.0.2 patch chain)

These are all fixed in this release; included for completeness for anyone who hit one of them.

### `v2-check` / `v2-start` / `v2-stop` / `uninstall` auto-detect the stack root

When the orchestrator is invoked from `<X>/bin/<self>` and `<X>` carries the v2 layout markers (`frontend-dist/` or `bin/ncc-api-server*`), the install-dir defaults to `<X>` instead of the legacy `<cwd>/.ncc-v2`. Secondary paths default to `<install-dir>/<name>` (config, outputfiles, nccfiles, .ncc-api-token). When `config.yaml` is absent, the orchestrator falls back to `<install-dir>/example_config.yaml` with an informational warning so first-run UX never blocks on a missing config.

Pinned by `TestDefaultV2InstallDir_*` in `goNCC_test.go`.

### `--repo-root` for the api-server now contains everything it touches

The api-server's `--repo-root` is its path-traversal sandbox: every file path it accepts (config, output-dir, log-dir, token-file, downloaded artifacts) must live inside it. v2.0.0 / v2.0.1 hardcoded repo-root to `os.Getwd()`. With install-dir auto-detect, `<install-dir>` may be a *parent* of CWD (when the user is in `<X>/bin/`), so config / outputs / logs landed outside the jail and the api-server rejected them.

`runV2Start` and `runV2Bootstrap` now compute `repo-root = ancestor(install-dir, cwd)` and pre-resolve symlinks. The latter is important on macOS where `/tmp` is a symlink to `/private/tmp`: the api-server `EvalSymlinks` its `rootAbs` but compared against the user-supplied (unresolved) abs path, so without orchestrator-side resolution the prefix check failed legitimate paths.

`resolveV2PathToReal` walks up the path until it finds an existing ancestor for not-yet-created paths so partial paths still resolve consistently.

Pinned by `TestResolveV2RepoRoot`, `TestIsPathAncestor`, `TestResolveV2PathToReal_NonExistentSuffix`.

### `wait-ready` and the UI→API backend URL preserve the user's bound IP

`localHTTPURLFromListen` always rewrote `127.0.0.1:port` to `localhost:port`. On macOS, `localhost` resolves to `::1` (IPv6) before `127.0.0.1` (IPv4), so the wait-ready probe and the UI server's backend connection both targeted the wrong address family when the api-server was bound IPv4-only — yielding `connection refused` even though the api-server was healthy.

The helper now preserves the user-supplied host. For CORS, `loopbackAltOriginFromListen` adds `http://localhost:port` to the allow-list when the UI binds to a loopback IP, so browsers can reach the UI under either name without "blocked by CORS" errors.

Pinned by `TestLocalHTTPURLFromListen`, `TestLoopbackAltOriginFromListen`.

### `orchestrator_bin` is an absolute, executable path

`resolveV2OrchestratorBin` returned `./ncc-orchestrator` when the binary lived in CWD (correct for the orchestrator) but the api-server interpreted it relative to its own CWD (= repo-root), so any API-triggered run would have failed to spawn the orchestrator. Fixed to always return an absolute, symlink-resolved path.

Verified live by hitting `/api/v1/health` and checking the reported `orchestrator_bin` is executable.

### Windows: `.exe` binaries are no longer rejected as "not executable"

`v2-check`, `v2-start`, and the api-server's startup guard tested the Unix executable bit (`mode & 0o111`) to decide whether a binary was runnable. Windows files have no such bit, so every shipped `ncc-*.exe` was wrongly flagged. On Windows this surfaced as:

- `v2-check` → `orchestrator-bin not executable` / `api-server binary not executable` / `ui-server binary not executable` (3 failures).
- `v2-start` → the api-server child immediately exited 1 with `orchestrator binary is not executable: …\ncc-orchestrator.exe`.

The executability test is now OS-aware (`v2layout.IsExecutable`): on Windows it checks the file extension against `PATHEXT` (default `.COM;.EXE;.BAT;.CMD`); on Unix it keeps the strict `mode & 0o111` bit check. `Unblock-File` is not required. Pinned by `TestIsExecutable`, `TestHasWindowsExecutableExt`, and `TestHasWindowsExecutableExt_RespectsPATHEXT` in `internal/v2layout/`.

### Windows publisher metadata + self-signed signing helpers

The embedded `VERSIONINFO` publisher string (`CompanyName`) is now a clean, properly-cased `NCC Orchestrator (open-source project)`, visible in **Properties → Details** and via `(Get-Item file).VersionInfo.CompanyName`. New `scripts/sign-windows.sh` (macOS/Linux build host) and `scripts/sign-windows.ps1` (native Windows) apply a **real Authenticode signature** with that publisher subject using a self-signed code-signing certificate, and export a public `.cer` so managed fleets can import it into *Trusted Publishers*.

> **SmartScreen note:** the "Publisher" line in *"Windows protected your PC"* comes **only** from an Authenticode certificate subject — `VERSIONINFO` does not affect it. A self-signed certificate is trusted only on machines that import it; clearing SmartScreen for the general public still requires a CA-issued (OV/EV) code-signing certificate. The public v2.0.2 binaries remain **unsigned**; verify them with `ncc-orchestrator verify` + `checksums.txt`. See `docs/SECURITY_AND_TRUST.md`.

### Side fixes shipped alongside

- **Extractor preserves the executable bit.** `extractTarGzArchive` / `extractZipArchive` use the mode in the archive header instead of hardcoded `0644`. Binaries inside `ncc-v2-stack-*.tar.gz` come out `0755` after `update`. Pinned by `TestExtractTarGzArchive_PreservesExecutableBit`.
- **`uninstall --remove-local` sweeps both layouts.** Adds install-dir-relative entries in addition to the existing CWD-relative ones. Belt-and-braces for `--remove-v2-runtime=false`.
- **`COPYFILE_DISABLE=1` + `--no-mac-metadata`** in `binaryGO.txt` so macOS-built tarballs don't carry `._*` resource forks.

## Backward-compatibility

- Scripts that passed explicit `--install-dir`, `--config-path`, `--output-dir`, `--log-dir`, `--token-file`, `--orchestrator-bin` continue to work unchanged. All new auto-detection logic is gated on "no explicit flag set" — explicit values always win.
- Legacy `v2-bootstrap --install-dir .ncc-v2 ; v2-check` from a project root still auto-detects nothing and falls back to `.ncc-v2` (the historical default), so existing first-run guides keep working. The example_config.yaml fallback simply removes a footgun.
- The package-level `update` flow introduced in 2.0.1 is unchanged.
- All new subcommands (`verify`, `doctor`, `v2-status`, `completion`) are pure additions — no existing subcommand was renamed or removed.

## Upgrade

From any v2.0.0 / v2.0.1 install:

```bash
./ncc-orchestrator update --allow-major-upgrade
```

Or manually re-extract the stack archive over the previous one — both forms are supported.

After upgrade, the recommended runtime invocation is now flag-free:

```bash
cd ncc-v2-stack-<os>-<arch>/bin
./ncc-orchestrator v2-start --api-listen :8081 --ui-listen :8080
```

Add `--detach --self-heal` to background with restart supervision. `./ncc-orchestrator v2-status` shows you what's running.

For a containerized deployment:

```bash
git clone <this-repo> && cd <this-repo>
mkdir -p config && cp example_config.yaml config/config.yaml
# edit config/config.yaml with your cluster credentials
docker compose up -d
# UI on http://localhost:8080
```

For first-time installs from a release tarball, see [`docs/SECURITY_AND_TRUST.md`](docs/SECURITY_AND_TRUST.md) for OS-specific quarantine bypass guidance and verification commands.

## Verification checklist for IT teams

A one-liner that exercises every layer of the trust stack:

```bash
./ncc-orchestrator verify                                 # embedded buildinfo + self SHA-256
shasum -a 256 -c checksums.txt                            # file integrity
gh attestation verify ncc-orchestrator-* --owner=<owner>  # SLSA build provenance
trivy sbom bom-ncc-orchestrator.cdx.json                  # SBOM-driven CVE scan (optional)
go version -m ./ncc-orchestrator | head                   # module list as recorded by Go
./ncc-orchestrator doctor --no-bundle                     # live runtime sanity
```

Each layer is independent: verifying any subset still produces a meaningful trust signal.
